#  **Prompt backend** 

Je veux que tu me crées un backend avec un code propre, en respectant le design pattern MVP. Voici mes règles pour un bon design :

1. **Modularité** : Divise chaque partie du code ou de la logique en composants, modèles et sous-composants pour éviter de modifier tout le code en cas de changement.  
2. **Règle des scouts** : Laisse le code plus propre que tu ne l’as trouvé, et évite les *magic numbers*.  
3. **Conventions de nommage** : Les variables doivent être des noms, et les fonctions des verbes.  
4. **Casse des noms** : Utilise le *camelCase* pour les variables et les fonctions, et le *PascalCase* pour les classes et les structures.  
5. **Évite l’imbrication profonde** : Privilégie une structure claire et peu imbriquée.  
6. **Fonctions courtes et concises** : Chaque fonction doit être courte, claire et faire une seule chose.  
7. **Documentation et concision** : Documente ton code et reste concis.  
8. **DRY (Don’t Repeat Yourself)** : Évite la duplication de code.
